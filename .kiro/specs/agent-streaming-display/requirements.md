# 需求文档

## 简介
DBAgent 当前前端在 Agent 执行期间的交互效果较差。Agent 思考时，中间推理文本（thinking text）通过 SSE 事件一次性整段输出，用户看到的是整块文本突然出现，缺乏实时感。工具调用步骤仅显示静态图标（⏳/✅/❌）和文字状态，没有动态效果，用户无法直观感知系统正在活跃工作中。

本功能为 DBAgent 前端增加流式逐字展示和工具调用动态效果：Agent 思考内容以打字机效果逐字渲染，工具调用步骤加入动态动画（文字脉冲/加载指示器），让用户实时感知 Agent 的思考过程和工作进度，提升交互体验。

## 边界上下文
- **范围内**：前端思考文本的逐字打字机渲染效果；工具调用步骤的动态动画（running 状态下的加载指示器/文字脉冲）；思考阶段与工具调用阶段的视觉区分；动画效果的 CSS 实现；动画与现有 SSE 事件流的对接
- **范围外**：修改后端 SSE 事件格式或发送频率（后端仍按现有粒度发送事件）；修改 Agent 执行引擎的思考/工具调用逻辑；WebSocket 传输协议的改动；图片或复杂 SVG 动画（仅使用 CSS 和文字效果）
- **相邻预期**：现有 SSE 事件流（step 事件中的 thinking/text 和 tool:* 步骤）继续作为数据源；`agent-cancel-thinking` 中的取消功能在触发时停止所有动画并清理状态；现有消息渲染管线（`updateStreamingMessage` → `finalizeStreamingMessage`）继续作为集成点

## 需求

### 需求 1：思考文本打字机效果
**目标：** 作为用户，我希望 Agent 的思考内容能逐字显示，以便实时跟随 Agent 的推理过程，获得即时反馈感。

#### 验收标准
1. When Agent 思考文本通过 SSE 事件到达，the 系统 shall 以逐字方式渲染到消息区域（打字机效果）
2. The 打字机效果 shall 以合理速度渲染（每字符约 20-40ms），使用户能舒适阅读
3. When 新的思考文本到达时前一段尚未渲染完成，the 系统 shall 将新文本追加到渲染队列中按序输出
4. When 思考阶段结束（进入工具调用或最终回答），the 系统 shall 立即完成剩余文本的渲染，不再逐字输出
5. When 打字机效果渲染过程中，the 系统 shall 自动滚动消息区域以保持最新内容可见

### 需求 2：工具调用步骤动态效果
**目标：** 作为用户，我希望看到工具调用步骤有动态视觉反馈，以便感知系统正在活跃执行操作而非卡住。

#### 验收标准
1. When 工具调用步骤处于 running 状态，the 系统 shall 显示动态加载指示器（如动画省略号"..."或脉冲文字效果）
2. When 工具调用步骤从 running 变为 completed，the 系统 shall 平滑过渡到完成状态（图标切换 + 动画停止）
3. When 工具调用步骤从 running 变为 error，the 系统 shall 显示错误状态并停止动画
4. When 多个工具调用步骤同时存在，the 系统 shall 仅对当前 running 的步骤显示动画效果

### 需求 3：分阶段进度提示
**目标：** 作为用户，我希望在 Agent 执行过程中清晰看到当前所处阶段和整体进度，以便实时了解工作状态，减少等待焦虑。

#### 验收标准
1. When Agent 开始执行，the 前端 shall 显示阶段进度指示器，标注当前正在执行的阶段名称。
2. When Agent 进入思考阶段，the 前端 shall 显示具体化的阶段描述（如"分析问题"、"生成回答"），而非仅显示通用标签。
3. When Agent 调用工具执行操作，the 前端 shall 将工具操作映射为人类可读的阶段描述（如"搜索数据库表"、"执行 SQL 查询"、"查看表结构"），让用户明确知道 Agent 当前在做什么。
4. The 前端 shall 维护并展示已完成阶段的列表，用户可回顾 Agent 已执行过的步骤轨迹。
5. When 工具执行完成，the 前端 shall 将该阶段标记为已完成状态，与正在执行的阶段形成视觉区分。
6. When Agent 在工具调用后再次进入思考阶段，the 前端 shall 更新阶段指示器反映当前进度位置，而非重复显示之前的阶段。
7. When 全部执行完成，the 前端 shall 将所有阶段标记为完成，并显示最终完成状态。
8. While 阶段进度指示器显示中，the 前端 shall 保持消息区域自动滚动，确保当前阶段始终可见。
9. If 用户取消执行，the 前端 shall 保留已完成阶段的显示，并将当前阶段标记为已取消状态。

### 需求 4：动画效果的 CSS 实现与性能
**目标：** 作为前端开发者，我希望动画效果使用纯 CSS 实现，不依赖第三方动画库，以便保持项目轻量且不影响页面性能。

#### 验收标准
1. The 系统 shall 使用 CSS animation 和 transition 实现所有动态效果，不引入第三方动画库
2. When 流式消息被最终确定（finalize），the 系统 shall 清除所有动画效果，释放资源
3. When 页面同时存在多个动画（打字机 + 工具步骤动画），the 系统 shall 保持页面流畅（不卡顿）
4. When 用户切换到其他会话或发送新消息，the 系统 shall 停止当前流式消息的所有动画

### 需求 5：异常场景降级
**目标：** 作为系统，我希望在动画渲染异常时不影响核心消息展示功能，以便用户始终能看到 Agent 的回复内容。

#### 验收标准
1. When 打字机渲染队列发生异常，the 系统 shall 立即显示全部已缓冲的文本，不阻塞后续消息处理
2. When 浏览器不支持 CSS animation，the 系统 shall 降级为静态展示（当前行为），不影响消息内容展示
3. When SSE 事件到达速度超过打字机渲染速度，the 系统 shall 限制最大延迟（不超过 3 秒），超出时加速渲染
