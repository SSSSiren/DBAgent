# 需求文档

## 简介
本项目旨在为 DBA 团队及研发人员提供一个 Web 部署的 NL2SQL 查询助手。用户通过自然语言描述查询需求，系统自动生成可执行的 SQL 语句并展示查询结果。系统支持多用户访问，每个用户拥有独立的会话管理和记忆存储，确保数据隔离和个性化体验。

## 边界上下文
- **范围内**：用户身份标识、会话持久化、多用户隔离、自然语言转 SQL 生成与校验、查询结果基础展示（表格、行数、SQL 可见、复制）、Web 聊天界面
- **范围外**：完整用户认证系统（密码/SSO）、高级数据可视化（图表）、SQL 性能优化与分析、DDL/DML 数据变更操作、数据导出（CSV 等）
- **相邻预期**：OneDBA 平台提供数据库连接与 SQL 执行能力；OpenViking 提供长期记忆存储服务

## 需求

### 需求 1：用户身份与访问控制
**目标：** 作为 DBA 或研发人员，我希望通过简单的身份标识访问系统，以便系统能区分不同用户并提供隔离的服务体验。

#### 验收标准
1. When 用户首次访问系统，the 系统 shall 要求用户提供唯一的用户标识（user_id）
2. When 用户提供有效的用户标识，the 系统 shall 为该用户创建独立的上下文空间
3. While 用户已标识身份，the 系统 shall 确保该用户仅能访问自己的会话、查询历史和记忆数据
4. If 用户提供的标识为空或无效，then the 系统 shall 拒绝访问并提示输入有效标识

### 需求 2：会话生命周期管理
**目标：** 作为用户，我希望创建和管理多个独立的查询会话，以便按不同主题或项目组织我的查询工作。

#### 验收标准
1. When 用户创建新会话，the 系统 shall 生成唯一会话标识并初始化空白会话上下文
2. When 用户切换会话，the 系统 shall 恢复该会话的完整上下文（包括对话历史、选中的数据库和表信息）
3. When 用户查看会话列表，the 系统 shall 展示该用户所有会话及其基本信息（创建时间、最近活动时间、会话摘要）
4. When 用户删除会话，the 系统 shall 移除该会话及其关联的所有数据
5. The 系统 shall 在服务重启后保留所有用户的会话数据和历史记录

### 需求 3：数据库发现与选择
**目标：** 作为用户，我希望浏览和搜索可用的数据库和表，以便选择正确的数据源进行查询。

#### 验收标准
1. When 用户搜索数据库，the 系统 shall 返回用户有权限访问的数据库列表，支持关键词模糊匹配
2. When 用户选择数据库后搜索表，the 系统 shall 支持跨数据库关键词搜索并返回匹配的表名列表
3. When 用户查看表结构，the 系统 shall 展示该表的完整字段信息（字段名、类型、是否可空、键类型、默认值）
4. When 用户选定了数据库，the 系统 shall 在后续查询中默认使用该数据库上下文

### 需求 4：自然语言转 SQL 查询
**目标：** 作为用户，我希望用自然语言描述查询需求，系统自动生成正确、安全的 SQL 并执行，以便我无需手写 SQL 即可完成数据查询。

#### 验收标准
1. When 用户输入自然语言查询需求，the 系统 shall 基于选定的数据库和表结构生成对应的 SQL 语句
2. When 生成的 SQL 包含安全风险（如 DDL/DML 操作），the 系统 shall 拒绝执行并提示用户
3. When 生成的 SQL 校验失败，the 系统 shall 尝试自动修复并重新校验，最多重试一次
4. When SQL 执行成功，the 系统 shall 返回查询结果并展示生成的 SQL 语句
5. When SQL 执行失败，the 系统 shall 向用户展示错误信息并提供修正建议
6. If 用户查询需求不明确或缺少必要信息，then the 系统 shall 向用户提出澄清问题而非猜测执行

### 需求 5：查询结果展示
**目标：** 作为用户，我希望清晰地查看查询结果，包括数据表格、统计信息和生成的 SQL，以便验证查询正确性并进行初步分析。

#### 验收标准
1. When 查询返回结果，the 系统 shall 以表格形式展示数据，包含列名和行数据
2. When 查询返回结果，the 系统 shall 展示结果行数统计
3. When 查询返回结果，the 系统 shall 展示实际执行的 SQL 语句供用户审查
4. When 用户查看 SQL 语句，the 系统 shall 提供一键复制功能
5. When 查询返回空结果，the 系统 shall 明确提示"查询无结果"并展示执行的 SQL

### 需求 6：用户记忆与上下文
**目标：** 作为用户，我希望系统能记住我的查询上下文和偏好，以便在连续对话中提供连贯的查询体验。

#### 验收标准
1. When 用户在会话中连续提问，the 系统 shall 保留对话历史并在后续回答中引用上下文
2. When 用户查询涉及之前讨论过的表或数据库，the 系统 shall 优先使用已确认的数据源上下文
3. The 系统 shall 将用户的对话记录持久化存储，服务重启后仍可恢复
4. If 对话历史过长超出上下文窗口，then the 系统 shall 自动生成摘要并保留关键信息

### 需求 7：Web 界面
**目标：** 作为用户，我希望通过浏览器访问直观的聊天界面，以便便捷地使用 NL2SQL 查询功能。

#### 验收标准
1. When 用户通过浏览器访问系统，the 系统 shall 展示聊天式交互界面
2. When 用户输入查询消息，the 系统 shall 实时流式展示处理进度（工具调用步骤、SQL 生成、结果返回）
3. When 系统处理查询，the 系统 shall 展示当前正在执行的步骤（如"正在搜索表..."、"正在生成 SQL..."）
4. The 系统 shall 在界面上展示当前用户标识和当前会话标识
5. The 系统 shall 支持多用户同时访问，各用户会话互不干扰
