# 需求文档

## 简介
本项目旨在为 DBAgent 的 NL2SQL 查询助手增加操作层记忆能力。当前系统已接入 OpenViking 上下文数据库提供语义记忆（"用户关注告警领域"），但 Agent 在执行 SQL 查询时需要的精确技术元数据（表名、数据库名、schema_id、SQL 模式）无法从中获取，导致每次对话都需要从零开始搜索表。本功能在现有语义记忆基础上补充结构化操作记忆，自动记录每次成功查询的技术元数据，在后续对话中按需检索并注入 Agent 上下文，减少盲搜轮次。

## 边界上下文
- **范围内**：记录 Agent 成功执行 SQL 查询后的表名、数据库名、schema_id、查询次数、SQL 模式；在对话开始时根据用户输入检索匹配的偏好表；将检索结果注入 Agent 上下文
- **范围外**：替换 OpenViking 语义记忆（本功能是补充，不是替代）；用户身份信息的存储；SQL 查询结果的缓存
- **相邻预期**：OpenViking 继续提供语义记忆（用户画像、行为偏好）；会话存储系统提供持久化能力

## 需求

### 需求 1：查询偏好自动记录
**目标：** 作为 Agent，我希望每次成功执行 SQL 查询后，系统自动记录该查询涉及的技术元数据，以便后续对话中复用。

#### 验收标准
1. When Agent 成功执行 `query_database` 工具并返回查询结果，the 系统 shall 自动记录该次查询涉及的表名、数据库名、schema_id 和查询时间
2. When 同一用户对同一张表多次查询，the 系统 shall 累计查询次数而非创建重复记录
3. When 查询涉及多张表（JOIN 场景），the 系统 shall 为每张表分别记录偏好
4. When 记录失败（如存储异常），the 系统 shall 静默降级，不影响正常对话流程

### 需求 2：偏好表按需检索
**目标：** 作为 Agent，我希望在对话开始时能根据用户输入的关键词，检索到与之匹配的历史偏好表，以便快速定位数据源。

#### 验收标准
1. When 用户输入包含与历史表名相关的关键词，the 系统 shall 返回匹配的偏好表列表，按查询频率降序排列
2. When 用户输入不包含任何可匹配的关键词，the 系统 shall 返回该用户最常用的表列表
3. When 用户首次使用系统（无历史偏好），the 系统 shall 返回空列表，不阻塞正常对话流程
4. The 系统 shall 确保用户 A 的偏好检索结果不包含用户 B 的数据

### 需求 3：偏好信息注入 Agent 上下文
**目标：** 作为 Agent，我希望在对话上下文中看到检索到的偏好表信息，以便在生成 SQL 前优先使用已知的数据源。

#### 验收标准
1. When 偏好检索返回非空结果，the 系统 shall 将偏好表信息注入 Agent 上下文，包含表名、数据库名和查询次数
2. When 偏好表信息已注入上下文，the 系统 shall 使其与 OpenViking 语义记忆并列展示，明确区分两类信息
3. When 偏好表信息为空，the 系统 shall 不在上下文中添加空段落

### 需求 4：用户感知
**目标：** 作为用户，我希望感知到系统记住了我的查询偏好，以便建立对系统记忆能力的信任。

#### 验收标准
1. When 对话开始时检索到偏好表，the 系统 shall 在前端记忆指示器中展示偏好表数量
2. When Agent 在回答中使用了偏好表信息，the 系统 shall 在回答中自然提及（如"根据你之前的查询记录..."）

### 需求 5：与现有记忆系统共存
**目标：** 作为系统运维者，我希望操作层记忆与语义记忆互不干扰，各自独立运作。

#### 验收标准
1. The 系统 shall 独立管理操作层记忆和语义记忆，一方的启停不影响另一方
2. When OpenViking 不可用时，the 系统 shall 仍正常记录和检索操作层记忆
3. When 操作层记忆存储异常时，the 系统 shall 不影响 OpenViking 语义记忆的正常工作
