# 实施计划

- [ ] 1. (P) 上传器：存储路径迁移与目录结构重构

- [ ] 1.1 切换 HDC 知识库根路径
  - 将 HDC 存储根路径从 memory 路径改为 resources 路径
  - 路径切换后，OpenViking 的 SemanticProcessor 应自动对上传内容生成 L0/L1 层级摘要
  - 验证：新建一张表后，其目录下出现 `.abstract.md` 和 `.overview.md` 文件
  - _Requirements: 1.1, 1.3_
  - _Boundary: Uploader_

- [ ] 1.2 新增列子目录 URI 辅助函数
  - 新增一个 URI 辅助函数，返回表目录下 `_columns/` 子目录的完整路径
  - 遵循现有 URI 辅助函数的命名和签名模式
  - 验证：给定 key 和表名，函数返回正确的 `_columns/` 子目录 URI
  - _Requirements: 1.1, 1.4_
  - _Boundary: Uploader_

- [ ] 1.3 重构单表上传逻辑，将列描述与表描述分离存储
  - 在上传单表时创建 `_columns/` 子目录
  - 将各列的描述文件写入子目录，而非表目录
  - 表描述 `_INDEX.md` 和 tags 保持在表目录不变
  - SemanticProcessor 处理失败时记录警告日志，继续处理后续表
  - 验证：上传完成后，表目录仅含 `_INDEX.md`，所有列 `.md` 文件位于 `_columns/` 子目录
  - _Requirements: 1.1, 1.3_
  - _Boundary: Uploader_

- [ ] 2. (P) 检索器：参数优化与评分算法改进

- [ ] 2.1 更新第一阶段检索参数
  - 将检索层级从 L2 全文改为 L0/L1 语义摘要
  - 将检索返回数量上限从 60 提高到 200
  - 新增相似度阈值 0.25，过滤低分噪音
  - 验证：检索返回表级匹配结果，低分噪音被过滤
  - _Requirements: 1.2, 2.1, 2.2_
  - _Boundary: Retriever_

- [ ] 2.2 实现表级匹配分数的多证据累积评分算法
  - L0/L1 表级检索可能返回同一张表的多个匹配项（如 `.abstract.md` 和 `.overview.md`）
  - 将表评分从"取单个匹配项最高分"改为"取全部匹配项中最高的 3 个分数求和"
  - 按综合评分降序排列候选表
  - 验证：多匹配项的表（同时匹配 abstract 和 overview）排名高于仅单一匹配的表
  - _Requirements: 3.1, 3.2_
  - _Boundary: Retriever_
  - _Depends: 2.1_

- [ ] 2.3 新增业务实体标识提取辅助方法
  - 读取表 `_INDEX.md` 首行内容，提取业务实体标识
  - 首行为空或无法解析时，回退使用表名作为实体标识
  - 验证：方法能从 index 文件中正确提取 main_entity，异常时回退到表名
  - _Requirements: 4.1, 4.2_
  - _Boundary: Retriever_

- [ ] 2.4 实现业务实体爆炸半径控制
  - 在 Top 5 截断前，限制同一业务实体下最多 2 张表进入最终结果
  - 超出限制的表被跳过，由后续排名的不同实体表递补
  - 验证：最终 Top 5 中同一业务实体的表不超过 2 张
  - _Requirements: 4.1, 4.2_
  - _Boundary: Retriever_
  - _Depends: 2.2_

- [ ] 2.5 更新列检索目标路径指向 `_columns/` 子目录
  - 将列检索的目标目录从表目录改为 `_columns/` 子目录
  - `_columns/` 子目录不存在时，回退到表目录检索
  - 验证：列描述从新路径正确检索，旧格式路径下也能正常工作
  - _Requirements: 1.4_
  - _Boundary: Retriever_

- [ ] 2.6 适配表名提取逻辑以识别 `_columns/` 路径
  - 在 URI 解析中识别 `_columns/` 路径段，将其父目录作为表名
  - 保持对旧格式路径的解析兼容
  - 验证：新旧两种格式的列文件 URI 都能正确提取表名
  - _Requirements: 1.4_
  - _Boundary: Retriever_

- [ ] 2.7 实现旧格式知识库的向后兼容回退
  - L0/L1 检索无结果时，自动回退到 L2 全文检索
  - 两次检索均无结果时，静默返回空结果，不阻塞对话流程
  - 验证：旧格式知识库（无 L0/L1）无需迁移即可继续正常检索
  - _Requirements: 2.3, 5.1_
  - _Boundary: Retriever_
